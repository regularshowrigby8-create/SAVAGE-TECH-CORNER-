# Imported factory catalog

The registry of external **software factories** this repository composes into its multistage
pipeline. Machine-readable form: `tools/factory/imported_factories.json` (consumed by the factory
runtime and pinned by `shell/tests/test_imported_factories.py`).

## How these were found (method, so the list can be reproduced or challenged)

1. Twelve GitHub searches for the pattern this repository implements - staged software production
   with AI workers - over `in:name,description,readme`, exact phrases (`"software factory"`,
   `"agent factory"`, `"ai workers"`, `"issue to pull request"`) and topics
   (`software-factory`, `agentic-ai`+`pipeline`, `ai-agents`+`orchestration`). 869 repositories were
   returned; 72 unique candidates came out of the noise filter (no "awesome-", no
   skills/tutorial/course collections).
2. Each candidate's **actual repository contents** were then read through the GitHub API - the
   root tree and the README - and scored by how many of six factory characteristics are really
   present: worker/agent code, stages, orchestration, factory naming, verification/review, and
   build/test/ship steps. Only repositories showing at least four of the six were kept.
3. The result: **106 verified factories**, of which **82 show AI-worker code**. Every field below
   (licence, stars, size, evidence) was read from the repository's own metadata on `2026-10-14`, not
   inferred. The registry is a point-in-time snapshot; stars and licences change.

## Import classes, and why they are not the same thing

| Class            | Meaning                                                                                                                                                                                                                  | Count |
| ---------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ----- |
| `asset-import`   | The licence permits reuse (MIT / Apache-2.0 / BSD / CC0). Stage designs may be adopted here, and individually reviewed assets may be vendored with their `LICENSE` and provenance hash.                                  | 79    |
| `blueprint-only` | No licence, or a copyleft one (AGPL/GPL). **No code or text is copied from these.** They contribute a blueprint: the stage and worker structure is described and re-implemented here from their published documentation. | 27    |

Nothing in this repository is a vendored clone of any of them: importing whole repositories would
mean multi-gigabyte additions, third-party dependency trees, and in 29 cases code that carries no
licence at all. What crosses the boundary is the _design_ - stages, worker roles, hand-offs, gates -
re-implemented against this repository's own conventions, plus (for `asset-import` entries)
individually reviewed assets with attribution.

## Rules this catalog is held to

- Every entry has a licence, a URL, a snapshot date, at least four verified characteristics, and a
  stable id; `shell/tests/test_imported_factories.py` fails if that stops being true.
- An entry may be `asset-import` only if its licence is one of the permissive identifiers the
  registry allows - a repository with no licence can never be re-classified by editing a string.
- No entry may be added or removed silently: the test asserts a floor of 50 entries and that the
  AI-worker subset stays the majority of the catalog, because that is what this factory is for.
- Attribution is per entry: `full_name`, `url` and `license` travel with every stage that came out
  of it.
